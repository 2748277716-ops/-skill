# 城市面板对齐技能 OOXML 定向读取设计

## 背景

现有 V2 读取链路虽然命名为“快速读取”，但预检和正式处理都会先调用
`SpreadsheetFile.importXlsx` 完整导入工作簿。实际试用发现两个问题：

1. 某些由 WPS 或其他工具保存的工作簿包含未被 `workbook.xml` 引用的孤立关系。
   Excel/WPS 可以正常打开，但严格的 Open XML 导入器会因目标部件不存在而报
   `PartDoesNotExist`。
2. 大型工作簿即使移除孤立关系，完整导入仍可能超过 120 秒，无法满足快速预检和
   指标精简处理的目标。

本次更新采用 OOXML 定向读取，源文件保持只读，最终工作簿仍由
`@oai/artifact-tool` 创建和复核。

## 目标

- 预检不完整导入源工作簿。
- 精简模式只物化城市、年份和用户指定指标列。
- 完整行模式仍读取并保留全部源列值。
- 自动忽略未被工作簿引用的孤立关系。
- 实际引用的工作表或必要部件缺失时暂停，不猜测、不修复源文件。
- 保留现有排序、全部实际年份、范围外城市追加、公式缓存值、缺失键和双向核验规则。
- 不修改源文件、城市顺序表或长期映射文件。

## 非目标

- 不修复或重写用户的源工作簿。
- 不复制源格式、批注、超链接或填充色到快速模式输出。
- 不对公式重新计算。
- 不把宽表改造成精简指标模式。
- 不引入新的系统依赖或第三方安装步骤。

## 方案选择

采用方案 A：使用已捆绑的 `JSZip` 读取 ZIP/OOXML 部件，输入读取不再依赖
`artifact-tool` 的完整导入。`artifact-tool` 只负责最终结果的创建、导出和重新导入核验。

未采用以下方案：

- 临时修复副本后完整导入：仍无法解决大型工作簿超过 120 秒的问题。
- 要求用户手工另存为：不能形成稳定、自动化的技能能力。

## 架构

### 1. OOXML 包检查器

新增独立模块，职责是：

- 读取 `[Content_Types].xml`、`xl/workbook.xml` 和
  `xl/_rels/workbook.xml.rels`；
- 建立工作表名称、关系 ID、部件路径和可见状态的映射；
- 仅校验 `workbook.xml` 实际引用的工作表关系；
- 忽略关系文件中未被 `workbook.xml` 引用的孤立关系；
- 对实际引用但关系缺失、目标部件缺失、路径越界或 XML 无法解析的情况返回明确暂停证据；
- 计算输入文件 SHA-256。

### 2. 轻量预检读取器

预检仅提取：

- 工作表名称和状态；
- 使用范围或实际最大行列；
- 第一条有效表头行；
- 估算所需的数据行数和列数。

预检不创建完整二维矩阵，不读取全部单元格样式，也不调用
`SpreadsheetFile.importXlsx`。

### 3. 工作表值读取器

正式读取时解析：

- `xl/sharedStrings.xml` 中的普通和富文本共享字符串；
- 内联字符串、普通字符串、布尔值、错误值和数值；
- 公式文本及已有缓存值；
- 合并单元格范围；
- 单元格地址、源行号和源列号。

读取规则：

- 公式存在且缓存值可用时，输出缓存值并记录公式事件；
- 公式为错误值或缺少缓存值时暂停；
- 数据区域存在合并单元格时暂停；
- 空单元格保持 `null`；
- 不插值、不填补、不猜测类型。

### 4. 列投影

读取分为两个阶段：

1. 先读取表头并唯一识别城市列、年份列和用户指定指标列；
2. 再读取数据行。

`selected_indicators` 只物化上述列，并保留原始单元格地址作为核验依据；
`preserve_rows` 物化全部源列。

指标仍采用安全空格和全半角归一后的唯一精确匹配。不存在或出现多个匹配时暂停。

### 5. 与现有编排衔接

- `listWorkbookStructure` 改用 OOXML 包检查器。
- `estimateAlignmentModes` 改用轻量预检统计，不读取完整矩阵。
- `readWorkbookFast` 保持现有返回数据模型，但底层改用 OOXML 工作表值读取器。
- `runAlignmentV2` 在精简模式下把指标选择传给读取器，使列裁剪发生在对齐之前。
- 排序、城市匹配、年份规则、缺失键生成、正向核验和逐键反向核验继续复用现有模块。
- 最终写入和重新导入核验继续使用 `writeCleanResultWorkbook`。

## 安全边界

- 未被 `workbook.xml` 引用的孤立关系自动忽略。
- 被 `workbook.xml` 引用但缺失的关系或工作表部件必须暂停。
- 缺少必要的共享字符串、样式或工作表 XML 时，不自动生成替代部件。
- 源文件在处理前后必须保持相同 SHA-256。
- 任何临时测试产物只写入测试临时目录，验证后删除。

## 性能边界

- 预检复杂度以工作表结构和表头为主，不随全部单元格数量线性物化。
- 精简模式的内存矩阵宽度固定为城市列、年份列和指定指标列数量。
- 完整行模式仍与源单元格总量近似线性，但避免严格工作簿对象模型的额外开销。
- 不设置依赖机器绝对路径；只使用运行时加载入口提供的 Node.js 和捆绑依赖。

## 错误处理

新增或扩展暂停证据以区分：

- 工作簿包结构无法解析；
- 实际引用关系缺失；
- 实际引用部件缺失；
- 孤立关系已忽略；
- 指标列不存在或不唯一；
- 公式缓存值不可用；
- 数据区域存在合并单元格。

孤立关系属于兼容信息，不作为失败；其数量和目标可在预检结果中返回用于诊断。

## 测试

至少新增以下回归测试：

1. 未被工作簿引用的缺失工作表关系不会阻断预检和正式处理；
2. 被 `workbook.xml` 引用的工作表部件缺失时暂停；
3. 多工作表名称、关系 ID 和部件路径解析正确；
4. 共享字符串、内联字符串、数字、布尔值和空值读取正确；
5. 公式缓存值被使用并记录，错误或无缓存值暂停；
6. 合并单元格继续暂停；
7. 精简模式只返回城市、年份和指定指标列，并保留原始地址；
8. 完整行模式保留全部源列；
9. 现有 V2 单元和集成测试全部通过；
10. 使用真实大型工作簿完成预检计时和精简模式端到端临时输出验证；
11. 源文件和城市顺序表哈希前后一致。

## 验收标准

- 本次发现的孤立 `rId6` 工作簿可以直接完成预检，无需临时修复副本。
- 七个指定指标全部唯一匹配。
- 预检在 120 秒内完成。
- 精简模式输出仅含城市、年份和七个指标。
- 城市顺序表固定内容不变，范围外城市仅追加到结果末尾。
- 未指定年份时使用源文件全部实际年份并降序排列。
- 正向核验、逐键反向核验和输入哈希核验通过。
- 不生成派生城市顺序表、审计工作表或额外正式文件。
- 不执行视觉渲染，除非用户另行授权。
