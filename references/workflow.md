# 工作流状态机

## 状态

- `collecting`：收集路径、工作表、年份和输出位置，尚未读取数据。
- `preflight`：只读导入并检查文件、结构、城市名称、公式、范围和占用状态。
- `needs_confirmation`：存在可以由用户明确决定的事项，不得创建正式输出。
- `executing`：按照已确认配置进行纯转换。
- `verifying`：执行计数、键集合、对应关系、哈希和输出重导入核验。
- `passed`：正式输出已存在，且所有强制核验通过。
- `paused`：存在歧义、冲突或需要用户处理的问题；不得声称完成。
- `failed`：运行错误或核验失败；不得保留或交付误导性的正式输出。

只允许以下主路径：

`collecting -> preflight -> executing -> verifying -> passed`

任何阶段都可进入 `paused` 或 `failed`。用户决定后从 `preflight` 重新开始，不得从转换中途继续。

## 预检顺序

1. 解析并规范化绝对路径；确认源文件、城市顺序文件存在，输出路径不覆盖任何输入。
2. 计算源文件与城市顺序文件 SHA-256；存在映射表时同时计算其哈希。
3. 导入工作簿并列出工作表。多工作表且未显式选择时返回 `MULTIPLE_SHEETS`。
4. 读取 `城市顺序.xlsx`，要求序号连续、城市名非空且标准名唯一。
5. 读取 `城市名称映射表.xlsx`；要求原始名唯一映射到标准城市名，不得有一对多冲突。
6. 检查所选工作表的使用区域、表头、合并单元格、公式及当前计算值。
7. 识别城市列、年份列和指标结构；不唯一即暂停。
8. 完成城市名称解析、重复键、目标年份范围和多指标可靠性检查。
9. 仅在所有阻断项清零后进入执行阶段。

## 表型识别

### 长表

满足以下条件才识别为长表：

- 有且仅有一个可靠城市列；
- 有且仅有一个可靠年份列；
- 每个数据行可形成城市—年份键；
- 其他列全部作为原行的一部分保留。

排序时移动完整行。标准城市名写回该行的城市列；年份值规范为整数但不得改变含义。多个指标列不影响完整行移动。

### 宽表

满足以下条件才识别为宽表：

- 城市位于行；
- 两个或更多可可靠解析的年份位于列；
- 非年份列视为辅助列并全部保留；
- 年份列单元格是该指标的值。

展开时每个源城市—年份单元格生成一行，并复制该城市行的辅助列。输出追加 `年份` 和指标列。默认一个工作表一个指标；多指标只在列分组、名称和共享城市—年份网格均唯一时启用。

## 城市匹配顺序

对每个源城市名依次尝试：

1. 标准名称精确匹配；
2. 安全归一化匹配：去除首尾空格、删除名称内部所有常见空格、全角空格转半角；
3. 唯一行政后缀匹配，例如唯一的 `厦门` 对应 `厦门市`；
4. 已确认的长期映射；
5. 模糊候选。模糊候选只提供证据，不自动写入、不继续正式输出。

安全归一化或唯一后缀匹配成功后，结果城市列使用 `城市顺序.xlsx` 中的标准名称。无法唯一对应时返回暂停。

## 执行与最少操作

- 只改变完成城市与年份对齐所必需的位置和城市标准名。
- 不删除、不合并、不改名任何源辅助列。
- 不改变数值、单位、精度、空值含义或业务口径。
- 公式单元格写入已缓存的当前计算值，并在审计中记录源地址、公式和写入值。
- 缺失键生成空白行：仅城市和年份有值，其他单元格为 `null`。
- 可安全对应的单元格格式、评论和普通超链接随源记录移动；无法证明对应安全时暂停。

## 核验

必须同时通过：

1. 城市顺序与城市基准完全一致；
2. 每个城市的年份严格按目标范围降序；
3. 输出键集合等于完整城市×年份集合；
4. 输出键无重复；
5. 正向核验：每个源内有效键及其各列内容可在输出找到唯一对应；
6. 逐键反向核验：每个非缺失输出键能追溯到唯一源记录或源单元格；
7. 缺失行除城市、年份外全部为空；
8. 公式输出为当前计算值，不残留普通公式；
9. 输出重导入后的值、公式、格式、评论和超链接符合能力边界；
10. 源文件、城市顺序文件哈希与预检值一致。

任何强制核验失败都返回 `failed`，不能降级为警告。

## 运行器配置与调用

`runAlignment(config)` 接受以下 JSON 可序列化字段：

```js
{
  inputPath: "C:\\data\\source.xlsx",             // 必填，源工作簿
  cityOrderPath: "C:\\data\\城市顺序.xlsx",      // 必填，只读
  mappingPath: "C:\\data\\城市名称映射表.xlsx",  // 可选，默认同目录
  selectedSheets: ["Sheet1"],                       // 必填；多表必须明确列出
  cityOrderSheet: "Sheet1",                         // 城市顺序文件多表时必填
  startYear: 2024,                                   // 必填，整数
  endYear: 2000,                                     // 必填，整数
  outputDir: "C:\\data",                           // 可选，默认源文件目录
  approvedSheetNames: {},                            // 源表名 -> 已批准输出表名
  approvedExcludedYears: [],                         // 用户明确允许排除的范围外年份
  confirmedMappings: []                              // 本轮用户明确确认的映射
}
```

`confirmedMappings` 每条记录使用：

```js
{
  sourceName: "厦冂市",
  standardName: "厦门市",
  matchType: "错字确认",
  confirmedAt: "2026-07-30T12:00:00+08:00",
  sourceFile: "source.xlsx",
  sourceSheet: "Sheet1",
  note: "用户确认"
}
```

执行方式：先用 `codex_app.load_workspace_dependencies` 获取 Node 运行时依赖目录，再用 `node_repl.js_add_node_module_dir({ path: 绝对node_modules路径 })` 注册依赖。之后在 `node_repl.js` 中使用新的 `var` 绑定，动态导入绝对 `scripts/run-align.mjs`，调用 `await module.runAlignment(config)`。不要使用静态 import，不要重复声明已有 `const`/`let`，不要从相对 `./node_modules` 路径导入包。

返回对象：

- `passed`：包含 `outputPath`、`outputSha256` 和 `audit`。检查正式文件存在、审计通过、输入哈希未变后才能交付。
- `paused`：包含 `code`、`message`、`evidence` 和预期输出路径。不得留下正式输出；一次只向用户请求一个决定。
- `failed`：包含 `code`、`message` 和错误证据。不得交付或声称完成。

城市错字确认后的恢复方式是：把确认记录加入 `confirmedMappings`，保留其他显式配置不变，并重新调用 `runAlignment`。工作表名或范围外年份获得批准时，分别更新 `approvedSheetNames` 或 `approvedExcludedYears` 后同样从头重跑。不要复用上一次内存中的行号、哈希或检测结果。

## 恢复规则

用户可确认：模糊城市映射、工作表选择、列选择、范围外年份排除。确认内容必须进入显式运行配置和核验记录。用户亲自修正源文件后，应重新计算哈希并从头预检；不得假设先前行号或单元格位置仍有效。
