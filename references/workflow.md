# V2 工作流

## 1. 只读估算

在任何写入前调用 `estimateAlignmentModes(config)`。按工作表报告：

- 行数、源列数；
- 完整行模式输出单元格量；
- 指标精简模式输出单元格量和减少比例；
- 两种模式预计时间、五小时额度与周额度；
- 推荐模式及信息保留差异。

估算是区间，不是承诺。公式、合并单元格、工作表数量、文件占用和复杂样式会影响实际时间。

## 2. 模式确认

- `preserve_rows`：保留长表全部列值；宽表展开后保留辅助列。
- `selected_indicators`：仅保留城市、年份和唯一精确匹配的指定指标列。

用户明确指定指标时推荐精简模式；需要归档、未知后续用途或要求完整行时推荐完整行模式。没有选择时只给建议，不写正式文件。

## 3. 年份

- `startYear`、`endYear` 均省略：读取源文件实际出现的全部唯一年份，降序排列。
- 两者均提供：使用包含端点的连续年份范围，降序排列。
- 只提供其中一个：`INVALID_CONFIG`。
- 默认全部年份不会补出源文件从未出现的中间年份。

## 4. 城市顺序

1. 验证 `城市顺序.xlsx` 的序号连续、城市名非空且不重复。
2. 标准城市按固定顺序排列。
3. 对源文件中未进入固定顺序的非空城市，记录首次出现位置。
4. 按首次出现顺序追加在固定城市之后。
5. 扩展只存在于本次运行内存中；不得修改或生成任何城市顺序文件。

范围外城市不写入 `城市名称映射表.xlsx`。空城市名、城市列歧义和重复城市—年份键仍暂停。

## 5. 指标选择

精简模式必须提供 `selectedIndicators`：

- 对表头做 NFKC、空格和大小写归一；
- 只允许唯一精确匹配；
- 找不到返回 `INDICATOR_NOT_FOUND`；
- 多个同名列返回 `AMBIGUOUS_INDICATOR`；
- 不做模糊匹配，不根据相似词猜指标；
- 输出列固定为城市、年份、用户指定指标顺序。

## 6. 快速读取与写出

`readWorkbookFast` 只读取：

- 数据区域值；
- 公式和当前计算值；
- 源单元格地址；
- 必需的工作表、行列和哈希信息。

默认不逐单元格读取或复制填充色、字体、批注、超链接，避免样式误写和额外耗时。

`writeCleanResultWorkbook`：

- 只生成一个结果工作簿；
- 默认仅包含结果工作表；
- 表头只使用加粗，不设置填充色；
- 写出后重新导入，比较完整二维值并确认不存在公式；
- 输出文件存在时暂停，不覆盖。

## 7. 核验

完成前必须通过：

1. 城市顺序等于固定城市加首次出现顺序的范围外城市；
2. 每个城市年份降序；
3. 输出键唯一；
4. 每个源城市—年份记录在输出中唯一对应；
5. 每个非缺失输出记录能反向追溯到唯一源行；
6. 精简模式每个指标值来自同一源行对应列；
7. 缺失行除城市、年份外为空；
8. 输出重新导入后的二维值完全一致；
9. 源文件和城市顺序文件哈希未变化；
10. 只生成一个正式结果文件，没有派生顺序表或审计工作簿。

## 8. 配置示例

```js
const config = {
  inputPath: "C:\\data\\source.xlsx",
  cityOrderPath: "C:\\data\\城市顺序.xlsx",
  cityOrderSheet: "Sheet1",
  selectedSheets: ["数据"],
  outputDir: "C:\\project\\处理后数据",
  outputMode: "selected_indicators",
  selectedIndicators: ["可支配收入"],
  // startYear/endYear 省略 = 源文件全部实际年份
};
```

先调用：

```js
await estimateAlignmentModes(config);
```

用户确认模式后调用：

```js
await runAlignmentV2(config);
```
