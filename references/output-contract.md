# 输出与核验契约

## 文件规则

- 输出目录默认是源数据文件所在目录。
- 文件名：`<源文件名>_城市面板对齐_YYYYMMDD-HHMMSS.xlsx`。
- 若同名文件已存在或被占用，暂停；不得覆盖、递增猜名或删除旧文件。
- 仅 `passed` 状态可以留下正式输出。预检和暂停证据写入运行日志或返回对象，不伪装成正式结果。

## 工作表

正式工作簿按需包含以下工作表：

1. `对齐结果`：用户用于检查和复制的数据。
2. `核验结果`：运行配置、数量、哈希和每项核验结论。
3. `城市匹配明细`：所有非精确匹配及其方法；没有时仍记录数量为 0。
4. `缺失键`：源数据没有的标准城市—年份组合。
5. `范围外数据`：仅在用户明确允许排除后创建，保留被排除的完整源记录或源单元格上下文。
6. `公式处理`：存在公式转值时创建，记录工作表、地址、公式、当前值和目标位置。

不得添加装饰性封面、图表、自动筛选、条件格式或无业务需要的工作表。

## 对齐结果列

### 长表

- 保留源表全部列及原列序。
- 城市列中的已匹配名称改为城市顺序文件中的标准名。
- 年份列保持原位置，输出值为目标年份整数。
- 完整行随城市—年份排序移动；不得逐列独立排序。
- 缺失键行只填写城市列和年份列，其他源列写入真正空值 `null`。

### 宽表转长表

- 按源顺序保留所有非年份辅助列。
- 追加 `年份` 列和指标值列；指标名采用可靠识别的工作表名或表头名。
- 每个城市—年份单元格生成一行；辅助列从同一城市源行复制。
- 多指标模式下，各指标列共享同一城市—年份键且能唯一对应，否则暂停。

## 排序

主排序键为城市在 `城市顺序.xlsx` 中的序号；次排序键为年份降序。每个城市必须连续出现，年份集合必须与显式目标范围完全一致。

## 内容保持

- 数字、字符串、布尔值、日期、错误状态和空值的语义不得改变。
- 普通公式写成当前计算值；目标单元格不得保留公式。
- 可安全映射时，源数据单元格的数字格式、填充、字体、边框、对齐、评论和普通超链接随记录移动。
- 仅由对齐产生的缺失行不复制任意源数据格式之外的内容；城市和年份可采用对应列的基础格式。
- 不自动调整列宽、行高、冻结窗格或样式。

## 核验结果字段

`核验结果` 至少记录：

- 运行时间和 Skill 版本/提交；
- 源路径、源 SHA-256、处理前后源 SHA-256；
- 城市顺序路径及 SHA-256；
- 映射表路径、执行前后 SHA-256 和追加条数；
- 选定工作表、表型、识别列、指标模式；
- 目标起止年份、城市数、期望键数；
- 源有效键数、输出行数、缺失键数、范围外记录数；
- 精确、安全归一化、后缀、长期映射和人工确认映射数量；
- 公式转值数量、评论/超链接转移数量；
- 城市顺序、年份顺序、唯一键、完整网格、正向对应、逐键反向对应、缺失行空白、公式转值、输出重导入、输入哈希不变的逐项结论；
- `visual_rendering`，未获许可时写 `not performed - user approval not requested`。

每个结论使用 `passed`、`paused` 或 `failed`，不得只写“已检查”。

## 运行器返回值

成功：

```js
{ status: "passed", outputPath, audit }
```

暂停：

```js
{ status: "paused", code, message, evidence }
```

失败：

```js
{ status: "failed", code, message, evidence }
```

`passed` 的前提是输出文件存在、可重导入、逐键反向核验通过且输入哈希未变化。调用方还应检查 `outputPath` 是新文件且不等于任何输入路径。

## 长期映射表

`城市名称映射表.xlsx` 与 `城市顺序.xlsx` 同目录，至少包含：原始城市名、标准城市名、确认时间、来源文件、来源工作表。只允许追加用户刚确认且不存在冲突的记录。追加前后均须验证既有记录集合未改变；写入失败或文件占用时正式输出一律暂停。
